`first()` and `last()` on query/model classes now preserve an explicitly set `order(...)` instead of silently re-sorting by model identity (primary key), which made `LIMIT 1` return an arbitrary row for ordered queries. The deterministic identity order is applied only as a fallback when no order was set: `first()` reads from the front of the ordered result and `last()` from its end. `last()` reverses the effective direction of each explicit order — including plain string orders such as `order("name DESC")` — through independent reversed order descriptors, so the source query's orders are never mutated for later reuse.
