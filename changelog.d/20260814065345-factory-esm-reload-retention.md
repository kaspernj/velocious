Bound unbounded factory-reload memory growth with a process-global cache-busted import budget. `reloadDefinitions` now preflights and reserves its whole resolved batch synchronously against a single process-global budget before any registry reset or import; a reload that would exceed the budget throws a typed `DefinitionRecycleRequiredError` with current/budget/requested counts while leaving the currently loaded registry fully usable, so long-running watchers deterministically stop and recycle/restart the owning Node process — the only boundary that reclaims Node's retained ESM definition modules. The budget can be configured exactly once before the first reservation; later attempts throw `DefinitionReloadConfigurationError` without resetting accounting. Every reload stays fully cache-busted (no top-level-content shortcut; edited top-level definitions stay visible in-process, edited dependencies on the next process recycle). The default budget (4096) is chosen from the new `benchmark/factory-esm-reload-retention` benchmark evidence (~6 KB retained heap per cache-busted import), which validates exactly eight 100/1,000-reload rows for unchanged and edited definitions across a single-process baseline and supervised whole-child-process recycle epochs, showing every generation stays within the deterministic import budget and edited dependencies are visible across recycle while reporting RSS without a brittle absolute threshold.
