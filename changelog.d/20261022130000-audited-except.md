# audited({except})

`Model.audited()` accepts an optional `except` list naming attributes that must never be written to the audit trail.

```js
Build.audited({
  except: [
    "executorHeartbeatAt",
    "executorProgressAt",
    "executorProgressEvent",
    "executorProgressSequence",
    "executorOutputByteCount"
  ]
})
```

Use it for high-frequency telemetry columns. Every audited update writes an `audit_actions` row inside the same transaction that holds the business row's X lock, so a column updated every few seconds per running record turns the audit table into a deadlock partner for the row it audits. Two such transactions can then cycle on `<table>` and `audit_actions.index_on_action`, and InnoDB rolls one of them back.

Excluded attributes are matched by attribute name or column name. Business attributes are still audited normally; create and destroy audits are unaffected.
