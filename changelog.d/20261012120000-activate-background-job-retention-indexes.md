Terminal background-job retention now uses composite indexes: routine readiness installs `(status, completed_at_ms, id)`, `(status, failed_at_ms, id)`, and `(status, orphaned_at_ms, id)` on `background_jobs` once per database, serialized by a migration advisory lock and recorded in the internal-migrations ledger so later readiness checks skip the DDL. MariaDB online index DDL can make concurrent schema-metadata inspection fail with error 1684 (`ER_WARN_I_S_SKIPPED_TABLE`), so the MySQL driver now classifies that error as transient and the base driver retries cached schema-metadata reads with bounded exponential backoff (250 ms to 2 s between attempts, 60 s total by default) instead of failing readiness or enqueue-time schema inspection while the index build is in flight.
