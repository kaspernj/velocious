Persist pooled-child acceptance evidence on the background jobs table: the epoch ms the executing pooled child's event loop processed the job message, the epoch ms its perform started, and that child's stable instance id and OS pid. The runner child reports both observations to the worker over IPC carrying the exact handoff lease; the worker forwards them through a new fenced store operation (`markChildAccepted`) that main acknowledges with the usual `job-updated` / `job-update-error` protocol, so a report for a reclaimed or re-handed-off job is dropped instead of stamping the wrong attempt. Evidence is cleared whenever the lease is invalidated (new handoff, reschedule, return to queue, failure retry) and kept on terminal outcomes as historical evidence for the lost attempt. The local store, the jobs web serialization, and generation-mode fencing accept the reports as well, so a `handed_off` job can be told apart from one whose runner never picked it up.
