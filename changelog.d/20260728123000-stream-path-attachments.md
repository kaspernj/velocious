Node `{path, filename?, contentType?}` record attachment inputs now keep one allowlisted, opened regular-file source plus its stat-derived byte size through normalization instead of materializing the whole file as a Buffer and Base64 string before storage. Filesystem persistence uses a bounded, backpressured stream and staged rename, S3 sends a Node `Readable`, pathname replacement cannot switch the source, truncation is rejected, later appends are ignored, and the source is always closed. Native callbacks retain their Base64 contract with compatibility buffering confined to the native driver, including preconstructed driver instances. Existing in-memory, UploadedFile, browser, legacy `content_base64`, replacement, and commit-aware cleanup behavior remains compatible.
