Terminal-job retention no longer blocks enqueues: `pruneTerminalJobs` selects bounded candidate pages outside the singleton count-revision mutation lock (deterministic ordering by terminal timestamp, then id), and only the short serialized transaction revalidates the selected ids, deletes the survivors, and publishes the count delta from the database's actual affected-row count — a concurrent pruner removing candidates first no longer makes a pass declare convergence early. Composite retention-index activation is deliberately deferred to a later release because MariaDB online index DDL is incompatible with schema inspection performed by older serving generations.
