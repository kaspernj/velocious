- Add a streaming (chunked) response API to the HTTP server: `response.stream()` opens a live chunked response, `response.write()` emits chunks to the client as they are produced, and `response.end()` terminates the stream; `response.isStreaming()`, `response.isStreamAborted()`, and `response.onStreamClose()` let a handler coordinate long-lived responses (e.g. SSE relays) and release resources when the client disconnects.
- Streaming chunks are delivered through the bounded, ordered client delivery queue: in-process handler mode settles each `response.write()` only after the chunk has been delivered to the socket, giving relay handlers socket backpressure and bounding what a stalled client can retain, while both in-process and worker-thread handler modes support the API. Malformed use (streaming after a buffered body, or after the stream ended) fails the request, and buffered responses are unchanged.
