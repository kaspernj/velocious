Background jobs now record `runner_hostname` alongside the accepting pooled child's `child_instance_id` and `child_pid`, and clear all three when a job is handed off again. The new `BackgroundJobRecord#ownerIsAlive()` answers whether the recorded local process still exists, and the `background-job-orphaned` event payload now carries the dead owner's identity so applications can release that owner's claims on the existing event instead of polling.
