Pooled background-job runners now report their live memory state: while a runner child has in-flight jobs it samples its own process and V8 heap statistics every ten seconds and sends a bounded observation over the child IPC channel (the pooled child's stdio is ignored by the worker fork, so IPC is the only path to the worker's log surface). The worker logs one compact JSON line per observation to its own stderr (which reaches the production log), records the latest observation on the child's state, and forwards it to an optional `onPooledRunnerMemoryObservation` worker constructor hook so an application can route memory diagnostics — for example to a bug reporter — without parsing logs. The heap-stat breakdown distinguishes V8-heap growth from external/array-buffer (native resource) growth, and the observation carries the in-flight job ids that were running at the sample. A worker helper (`requestPooledChildMemoryObservation`) also requests an immediate snapshot from one child on demand, without waiting for the next periodic sample.
