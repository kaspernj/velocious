Features: implement the opt-in file-lock fallback tier (STC-213, leg 5 of the STC-210 backend chain). `src/database/advisory-lock-file-backend.js` generalizes the directory-lock protocol from `src/http-server/server-lock.js` (now a thin wrapper over it) into a shared backend behind the advisory-lock seam: atomic publication via mkdtemp+rename, per-hold lease renewal, and stale-holder reclaim via lease expiry or local PID liveness. The tier is disabled by default and only selectable by explicit configuration (`advisoryLocks.backends.file.enabled: true` plus a per-lock-name policy with `minTier: "file"`); a lock name with a cross-host minimum tier is refused loudly with `AdvisoryLockMinTierRefusedError` (reported on the framework-error channel as `advisory-lock-min-tier-refused`) instead of silently served. Every acquisition reports the tier that served it (`lockBackend` in the callback args, `fencingSupported: false` for the file tier), and `configuration.getAdvisoryLockBackendStatus(lockName)` answers "which backend served this lock". The file tier consumes no database connection.
