Model initialization now loads schema metadata for all model tables in one batch per database instead of one catalog query per model. On a 71-model application spread over three databases (33 MySQL tables, 38 SQL Server tables) a single worker boot issued ~74 catalog queries — 33 `SHOW FULL COLUMNS`, 38 three-way `INFORMATION_SCHEMA` joins averaging 4 ms each against a remote legacy SQL Server — and every HTTP worker process repeated the whole sweep, so eight workers paid it eight times.

`SchemaMetadataPrefetcher` groups the model classes by database, includes each translated model's `<table>_translations` table, and asks the driver for `batchTableColumns(tables)`. MySQL/MariaDB and PostgreSQL answer with one `information_schema.COLUMNS` query mapped onto the metadata shape the per-table read produces, MSSQL drops the per-table filter from its existing join, and SQLite falls back to bounded-concurrency per-table reads. The result is seeded through the new `seedTableSchemaMetadata`, so `initializeRecord` resolves entirely from the driver's schema cache; the initialization loop itself now runs with bounded concurrency. Measured on that application: five catalog queries per worker boot instead of ~74, and no per-model column reads.

The MySQL batch is verified column-for-column against `SHOW FULL COLUMNS` across the 351 columns of a 44-table MariaDB schema; the only divergence found was MariaDB reporting a SQL `NULL` default as the literal string `'NULL'`, compensated with `NULLIF(COLUMN_DEFAULT, 'NULL')`. `spec/database/drivers/batched-table-columns-spec.js` asserts that parity on every database matrix leg that supports batching.
