Sync changes pages answer a caught-up sequence cursor without running the page read or the `total` count. A multi-scope client sends its global cursor to every scope it polls, so scopes whose own server sequences sit behind that cursor previously ran an impossible-range `SELECT` and a `COUNT` (`server_sequence <= <scope max> AND server_sequence > <global cursor>`) on every poll, always returning nothing. Pages served with a sequence cursor that are short of the requested limit also skip the count, because the page read already materialized the whole remaining set; the count still runs for full pages and for `updatedAt`-based cursors.
