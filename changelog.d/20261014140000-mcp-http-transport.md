MCP is now also served by the application's own HTTP server: `mcp: true` (or `mcp: {path, token}`) in the configuration exposes the same JSON-RPC methods (`initialize`, `ping`, `tools/list`, `tools/call`) at `POST /mcp` — no separate `velocious mcp` process needed. The request's `Authorization` header is forwarded as the request-context `authorization` key into every tool call, and tenant/ability resolution stays inside `FrontendModelController.frontendApi()` exactly like the shared `/frontend-models` endpoint. With `token` configured, unauthenticated requests are not routed (404), matching the `apiManifest`/`debugEndpoint` convention.
