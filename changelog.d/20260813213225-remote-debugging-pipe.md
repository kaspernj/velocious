Browser-test Chrome sessions now start reliably on headless container CI. The browser-test session launches Chrome with ChromeDriver's recommended `--remote-debugging-pipe` transport (alongside the existing headless container argument list) instead of letting ChromeDriver inject `--remote-debugging-port=0`, which let the Chrome instance exit before a Selenium session was created. The SystemTest factory that wires the pinned Chrome binary and those arguments now lives in `scripts/browser-test-session.js`.
