Add opt-in buffered HTTP response compression via `httpServer.compression` (`true` or an object with `threshold` default 1024, `brotliQuality` default 4, and `gzipLevel` default 6, validated with unknown-key rejection and exposed through `configuration.getHttpServerCompression()`). Buffered string and `Uint8Array` responses negotiate `br`/`gzip` from `Accept-Encoding` with case-insensitive strictly-parsed RFC q-values, wildcard, explicit-coding precedence, and identity semantics — identity quality is compared against the supported codings with equal-q ties in server order `br`, `gzip`, `identity`. When compression is enabled and the response has no application-supplied `Content-Encoding`, a forbidden-identity request that cannot be satisfied — no acceptable supported coding, or a skipped transformation with identity forbidden — is answered with an empty `406`, and the threshold never forces an unacceptable identity representation. Compressed responses set `Content-Encoding` and exactly one exact compressed `Content-Length` (any pre-set content-length header is replaced case-insensitively), merge `Accept-Encoding` into `Vary` case-insensitively without duplicates (preserving `Vary: *`), and use only asynchronous `node:zlib` APIs. Transformation is skipped for `sendFile`, existing `Content-Encoding`, `Cache-Control: no-transform`, `text/event-stream`, 206/Range/`Content-Range` responses, bodyless statuses, non-allowlisted content types, and per-response `response.disableCompression()` opt-outs. Response emission now serializes done-request draining per client so async compression cannot reorder pipelined responses, and HEAD requests compute GET-equivalent representation headers (including `Content-Length` and `Content-Encoding`) without emitting a body. Representation validators such as `ETag`/`Digest` remain application-owned and are not rewritten. See `docs/http-server.md#response-compression`.
